# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

A [NeoForge](https://neoforged.net/) mod for **Minecraft 1.21.1** bringing Brandon Sanderson's
Cosmere into the game. Mod id `cosmere`, package `com.cosmere`.

The content in the repo is **Scadrial**: Allomancy, Feruchemy and Hemalurgy in full, the mists,
and the creatures that come out of them. Other planets are planned but deliberately not
implemented -- see "Dimensions" below.

- Java 21 (Mojang ships Java 21 for 1.21.1; the toolchain enforces this)
- NeoForge `21.1.248`, Parchment mappings `2024.11.17`
- Gradle 9.2.1 via [ModDevGradle](https://github.com/neoforged/ModDevGradle) (`net.neoforged.moddev`)

## Commands

- `./gradlew build` — compile and produce the mod jar in `build/libs/`
- `./gradlew runClient` — launch a client with the mod loaded (run dir: `run/`)
- `./gradlew runServer` — launch a dedicated server (`--nogui`)
- `./gradlew runGameTestServer` — run the game tests headlessly and exit
- `python3 tools/generate_resources.py` — regenerate assets and data (see below)
- `python3 tools/generate_structures.py` — regenerate structure templates and their placement data

### Tests

Tests are NeoForge **game tests** in `com.cosmere.test.CosmereGameTests`, run with
`./gradlew runGameTestServer` or `/test runall` in-game. They cover the rules a compile cannot:
that every metal in the enum actually has its items registered, that alloy matching rejects
stray ingredients, the Identity rule on metalminds, spike granting and voiding, the spike
capacity limit, reserve burn-out, and that the Well of Ascension template loads.

They all use the `cosmere:test_platform` structure, which is generated by
`tools/generate_structures.py`.

## Architecture

### One enum drives the content

`com.cosmere.metal.Metal` is the source of truth for all twenty-one metals: its Allomantic,
Feruchemic and Hemalurgic categories, its colour, and whether the mod supplies its ore and
ingot. `ModItems` and `ModBlocks` walk it to register everything, the tickers switch on it, and
`tools/generate_resources.py` mirrors the same table to generate assets.

**Adding a metal** means: one entry in `Metal`, one case in each of `AllomancyTicker`,
`FeruchemyEffects` and `StolenAttribute.kindStolenBy`, one entry in each text table in
`tools/generate_resources.py`, then re-run the generator. Nothing else needs touching.

`com.cosmere.metal.Mineral` is the same idea for lead/silver/nickel/bismuth, which exist only
as alloy ingredients and have no powers.

### One attachment holds a player's Investiture

`com.cosmere.InvestitureData` is a single data attachment covering all three arts, because they
constantly read each other: Hemalurgy grants Allomancy, a nicrosilmind amplifies it, an
aluminum spike voids it. Keeping it in one object also means one sync packet.

The server is authoritative. `SyncInvestiturePayload` pushes a copy to the owning client, which
uses it only for the HUD and for deciding whether to send an input. Reach it with
`com.cosmere.util.Investiture.of(entity)` and re-sync with `Investiture.sync(player)` after any
change the client needs to see.

Transient fields (flaring, the F toggle, pewter debt, loaned powers) are deliberately not
serialised; they are re-established each tick or each session.

### Where the per-tick work happens

`ModEvents.onPlayerTick` is the single entry point, calling in order:

1. `AllomancyTicker.tick` — spend reserves, apply each burning metal's effect, resolve held Pushes
2. `FeruchemyTicker.tick` — move charge in and out of carried metalminds
3. `MistManager.tick` — mist atmosphere, mistwraith spawning, Snapping

### Client/server split

Client code sends *intent* (`network/c2s`) and draws what it is told; every rule lives server
side. `ClientPayloadHandler` deliberately touches no `net.minecraft.client` type so that
`CosmereNetwork` — a common class — can name its methods without breaking a dedicated server.

### Two event buses

- **Mod bus** — registration and lifecycle. Wired explicitly in the `Cosmere` constructor and in
  `ModBusEvents.register(modEventBus)`; client-side mod-bus events live in `CosmereClient`.
- **`NeoForge.EVENT_BUS`** — gameplay. `ModEvents` and `ClientEvents` subscribe via
  `@EventBusSubscriber`.

### Assets and data are generated, not hand-written

`src/main/resources/assets` and `src/main/resources/data` are **generated output**. Twenty-one
metals times six items each is not maintainable by hand, and NeoForge datagen would mean
restating the metal tables in Java.

`tools/generate_resources.py` writes every model, blockstate, sprite (procedurally, via a
hand-rolled PNG encoder in `tools/pngwriter.py` — no third-party dependency), lang key, tag,
recipe, loot table and ore feature. `tools/generate_structures.py` writes the structure NBT
directly via `tools/nbt.py`.

**Edit the generator, not the generated files.** Re-run both scripts from the repo root after
changing them.

### Mod metadata is generated too

There is **no** static `neoforge.mods.toml`. `src/main/templates/META-INF/neoforge.mods.toml` is
a template expanded by the `generateModMetadata` task from `gradle.properties`. Edit the
template and `gradle.properties`, never anything under `build/`.

## Dimensions

`com.cosmere.dimension.CosmerePlanets` fixes the shape of multi-planet support without
registering anything. Scadrial currently *is* the Overworld. When a real Scadrial dimension
arrives, only that enum's key changes and everything consulting `CosmerePlanets.of` follows.
Worldgen for a new dimension is datapack-driven in 1.21, so adding one needs JSON, not code.

Nothing in Scadrial's systems assumes it is alone — a Mistborn stays a Mistborn anywhere.

## Naming (keep in sync)

The mod id `cosmere` is threaded through coupled places. If it changes, update together:

1. `gradle.properties` — `mod_id`, `mod_name`, `mod_group_id`
2. `MODID` in `Cosmere`
3. The Java package `com.cosmere` and source directory layout
4. `MODID` in `tools/generate_resources.py`, then re-run both generators
5. `neoforge.enabledGameTestNamespaces` in `build.gradle` (currently `cosmere`)

`mod_id` must match `[a-z][a-z0-9_]{1,63}`.
